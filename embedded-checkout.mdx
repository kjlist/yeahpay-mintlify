## 产品简介

Embedded Checkout（嵌入式收银台）是一套以组件形式直接嵌入商户自有页面的收银能力：商户在自己页面中挂载收银台组件，买家无需跳转到第三方域名，就能在组件内完成填卡、3DS 验证与支付确认的全过程。卡号、有效期、CVV 等敏感信息仅在收银台侧采集和处理，不经过商户系统，相关 PCI DSS 合规责任由 Yeahpay 承担。

与跳转至托管页面的 Unified Checkout 不同，Embedded Checkout 把收银体验留在商户自己的页面内，更适合对转化率与品牌一致性要求更高的场景。

## 主要能力与优势

- **页面内收银，全程不跳转**：收银台以组件形式嵌入商户页面任意位置，买家全程停留在商户域名内完成支付，收银台加载成功率目标 ≥ 99%
- **卡字段独立承载，PCI 合规降至 SAQ-A**：卡号、有效期、CVV 由 Yeahpay 独立渲染与加密处理，商户页面与脚本外层读不到卡明细，安全码任何环节都不落库保存
- **内置绑卡与已存卡复购**：买家可在支付时完成绑卡，后续复购直接用已绑定的卡一键支付；单买家最多保存 20 张已绑卡，绑卡、查询、停用整套生命周期均由 Yeahpay 承载
- **3DS 验证原生承接**：卡组织要求的强身份验证流程在收银台组件内完成，不会打断买家在商户页面内的体验，天然适配欧盟、英国等强制 3DS 的地区
- **预授权与正式扣款灵活声明**：支持 Final Auth（即时扣款）与 Pre Auth（预授权，后续请款）两种授权类型，适配酒店、租车、押金等场景
- **状态事件实时外抛**：收银台向商户前端抛出加载完成、支付结束、出错等状态事件，商户页面可据此响应（发货仍须以服务端查询或异步通知为准）

## 接入使用流程

1. **创建 Payment Intent**：商户后端调用创建接口，传入金额、币种、商户订单号等信息，获得 Payment Intent ID 与 Payment Intent Token
2. **下发凭据至前端**：商户后端将 Payment Intent ID 与 Payment Intent Token（而非服务端凭据）传给页面
3. **加载并挂载收银台**：商户页面引入 Yeahpay 收银台脚本，用 Token 初始化并挂载到页面指定容器，组件自动渲染可用支付方式与该买家已存卡
4. **买家完成支付**：买家在组件内填写卡信息并提交，如渠道要求 3DS 验证，也在组件内原生完成，无需离开商户页面
5. **接收支付结果**：收银台将结果通知商户前端用于页面跳转；商户系统以服务端查询 Payment Intent 或接收异步通知为准，更新订单状态
6. **发起退款（如需要）**：凭 Payment Intent ID 或商户订单号调用退款接口，由现有退款体系完成退款或撤销

## 常见问题 FAQ

**Payment Intent Token 的有效期是多久？** 与所属 Payment Intent 同生命周期，默认 24 小时，不单独过期、不需要续签；Payment Intent 过期后需创建新订单并用新令牌重新加载收银台。

**支付失败后可以重试吗？** 可以。买家可在同一 Payment Intent 下更换支付方式或重新尝试，重试次数上限 10 次，直至 Payment Intent 过期（24 小时）。

**商户需要存储或处理持卡人卡号信息吗？** 不需要。卡号、有效期、安全码等敏感字段只在收银台组件内采集和处理，不经过商户系统，相关 PCI DSS 合规责任由 Yeahpay 承担。

**嵌入收银台时有什么限制？** 收银台脚本须从 Yeahpay 域名直接引入，商户页面须为 HTTPS 且域名需提前在商户后台完成注册审核，未注册域名的加载请求会被拒绝。

**买家可以保存多张卡吗？** 可以，单买家最多保存 20 张已绑卡，超过上限时淘汰最久未使用的一张；过期卡会保留但置灰不可选。

**目前支持哪些支付方式？** 本期仅支持卡（Visa / Mastercard / Amex 等，具体以商户签约范围为准），暂不支持钱包与本地支付方式。
