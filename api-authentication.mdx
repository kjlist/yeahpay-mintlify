使用对应环境的 `appId` 和 `apiKey`，在商户服务端为每个请求生成 SHA-512 签名。通过请求头传递 `appId` 和 `signature`。`apiKey` 仅用于服务端计算签名。

## 公共请求头

商户 API 使用 `POST` 和 JSON 请求体。各接口页面列出接口特有的请求头、请求体和响应字段。

| Header | 必填 | 示例 | 说明 |
| --- | --- | --- | --- |
| `appId` | 是 | `1000122333` | YeahPay 分配的应用 ID |
| `version` | 是 | `1.0` | 公共参数版本，固定为 `1.0` |
| `timestamp` | 是 | `1694082355494` | 13 位毫秒时间戳 |
| `nonce` | 是 | `FGHUdssdfs5sEDF` | 每次请求使用不同的随机字符串 |
| `algorithm` | 否 | `SHA-512` | 签名算法，默认 `SHA-512` |
| `signature` | 是 | `base64...` | SHA-512 摘要的标准 Base64 编码 |
| `Accept-Language` | 否 | `zh-CN` | API 响应语言 |
| `Accept-Timezone` | 否 | `Asia/Shanghai` | API 响应时区 |
| `Content-Type` | 是 | `application/json` | 请求体格式 |

## 生成签名

签名和发送请求时使用同一份原始 JSON。在[签名规则与示例](/signature)查看签名路径、字段顺序和代码示例，或用[签名调试工具](/api-tester)生成指定接口的签名和 cURL。接收支付或退款通知时，按[通知验签](/signature#通知验签)处理。
